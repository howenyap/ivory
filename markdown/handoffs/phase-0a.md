## Decisions and Assumptions
- The phase was kept intentionally bootstrap-only; later-phase business logic was explicitly out of scope.
- `argparse` from the standard library was used for the CLI skeleton instead of adding a CLI dependency.
- `tomllib` from the standard library was used for config loading.
- `.python-version` was pinned to `3.14.3` rather than `3.14` because `uv` selected a `3.14.0rc2` interpreter when the version was too loose.
- A build backend is present because the repo is package-based and `uv` needs to install the local project; `hatchling` was used after aligning to the `uv init` template.
- `prek` was configured with Ruff and `ty` even though that was not part of the original phase-0a markdown contract; it was explicitly requested later in this thread.
- The repo was not reinitialized destructively with `uv init` in place.
  - Instead, a fresh `uv init --package --app --build-backend hatch --python 3.14.3` template was generated in a temporary directory and the repo was manually realigned to it.

## Issues Encountered
- `uv sync` initially chose `CPython 3.14.0rc2` instead of `3.14.3` when `.python-version` was `3.14`.
- Direct removal of `.venv` with `rm -rf .venv` was blocked by policy in the tool environment.
- `uv run ruff check .` caught unsorted imports in `src/ivory/config.py`; this was fixed.
- After changing the package entry point to `ivory = "ivory:main"`, `uv run python -m ivory.cli --help` emitted a `RuntimeWarning` because `ivory.__init__` eagerly imported `ivory.cli`.
  - This was fixed by making the package-level `main()` import `ivory.cli` lazily.
- `uv run prek validate-config` printed `warning: No configs to check` even when `prek.toml` existed.
  - This remained unexplained in-thread.
- `uv run prek run ...` emitted warnings about invalid installed hooks under `~/.cache/prek/hooks/.../.prek-hook.json`, but the hooks still ran and passed.
